## 2. 총평

이번 lab04 모의해킹에서는 WPScan 사용자 열거 옵션으로 인한 사용자 노출, 유추하기 쉬운 비밀번호 사용, webshell.php 업로드 제한 정책의 부재, 불필요한 cron 실행 작업 잔재의 취약점 연계로 최종 root 권한 획득까지 이어졌다.
이는 외부에서 시작된 침해가 서버 전체에 대한 통제권 확보로 확대될 수 있음을 보여준다.

보완을 위해 Wordfence에서 사용자명 발견 방지 옵션을 켜서 열거 차단, 블로그에서 노출 되지 않은 길고 복잡한 비밀번호 설정, WAF, Apache 설정 파일을 이용한 PHP 접근 차단 혹은 PHP 파일을 코드로 실행하지 못하도록 별도 저장소에 업로드, 불필요한 예약 작업을 제거하고 필요한 예약 작업은 관리자만 관리 가능한 전용 디렉토리에서 실행하도록 하여 최소 권한으로 작업하도록 적용해야 한다.

### 6.1 WPScan 사용자 열거 옵션으로 인한 사용자 노출

  **6.1.1 설명**

- WPScan에서 --enumerate u 옵션으로 'admin'이 노출됐다.
- admin 계정으로 브루트 포스 공격을 하여 유추한 비밀번호로 계정 접속이 가능.

  **6.1.2 조치방법**

- Wordfence에서 사용자명 발견 방지 옵션을 켜서 열거 차단

### 6.2 유추하기 쉬운 비밀번호 사용

  **6.2.1 설명**

- 노출되어 유추하기 쉬운 비밀번호를 사용했다.
- 블로그에서 모아온 비밀번호 리스트로 브루트 포스 공격을 성공했다.

  **6.2.2 조치방법**

- 비밀번호를 길고 어렵게 설정한다.

### 6.3 webshell.php 업로드 제한 정책의 부재

  **6.3.1 설명**

- webshell.php 파일이 그대로 업로드 가능
- 쉬운 webshell.php 업로드로 인해 사이트에서 간단하게 웹쉘 실행 가능.

  **6.3.2 조치방법**

- WAF 단에서의 webshell.php 업로드 성공/실패 패턴 요청 탐지, 차단
- 사이트의 Apache 설정 파일에 업로드 폴더의 PHP 접근 차단 설정을 올린다.(AllowOverride None, Require all denied 옵션, php를 우회하도록 설정된 다른 확장자 차단)
- PHP 파일을 실행할 수 없는 별도 저장소에 업로드 하도록 구조적 분리를 하고, 업로드 파일을 코드로 실행하지 못 하도록 한다.

### 6.4 불필요한 cron 실행 작업 잔재

  **6.4.1 설명**

- 여러 사용자가 쓸 수 있는 /dev/shm 디렉토리에서 root 권한으로 실행 가능한 cron 명령이 잔재
- root로 실행 가능한 cron 명령이었기에 root 권한으로 리버스쉘이 실행되어 권한 탈취가 가능했다.

  **6.4.2 조치방법**

- 불필요한 예약 작업 제거
- 필요한 예약 작업은 관리자만 관리 가능한 전용 디렉토리에서 실행하도록 하여 최소 권한으로 작업.

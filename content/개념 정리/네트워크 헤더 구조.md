**PDU(Protocol Data Unit): 각 계층에서 주고받는 데이터 단위**

| 계층·프로토콜  | 일반적으로 부르는 PDU 이름          |
| -------- | ------------------------- |
| L2 — 이더넷 | 프레임(Frame)                |
| L3 — IP  | 패킷(Packet)                |
| L4 — TCP | 세그먼트(Segment)             |
| L4 — UDP | 데이터그램(Datagram)           |
| 응용 계층    | 메시지(Message) 또는 데이터(Data) |

<br><br>

# 1. 데이터 캡슐화의 과정

\===> **데이터는 Header들의 연속된 집합**

## 1.1 L1 : Physical Header

     => 수신 준비와 프레임 시작 표시

| 이름       | 크기 <br>(Bytes) | 설명                     |
| -------- | :------------: | ---------------------- |
| Preamble |       7        | 송신 측과 수신 측의 비트 타이밍을 맞춤 |
| SFD      |       1        | 프레임의 시작을 표시            |
| **총합**   |     **8**      | -                      |

✓ **Preamble은 이더넷 프레임 앞에 붙음**

10101010 7번 반복

```
Preamble: 7바이트 = 56비트
10101010 10101010 10101010 10101010 10101010 10101010 10101010
```

✓ **마지막 1 or 0 -> SFD**

```
SFD: 1바이트 = 8비트
10101011
```

<br><br>

## 1.2 L2 : Ethernet Frame Header

| 이름                      | 크기 <br>(Bytes) | 설명                   |
| ----------------------- | :------------: | -------------------- |
| Destination MAC Address |       6        | 받는 장치의 MAC 주소        |
| Source MAC Address      |       6        | 보내는 장치의 MAC 주소       |
| Type or Length          |       2        | 내부 프로토콜 종류 또는 데이터 길이 |
| **총합** (Header)<br>     |     **14**     | -                    |
| +                       |       +        | -                    |
| Data + Padding          |    46~1500     | 전달할 내용과 필요시 채우는 공간   |
| FCS                     |       4        | 전송 중 오류 검사용 값        |
| **총합** (Header+Trailer) |  **64~1518**   | -                    |
|                         |                |                      |

- Trailer: 프레임 뒤에 붙는 부분

## 1.3 L3 : IP Header

| 이름                                | 크기(Bytes) | 설명                                                                                      |
| --------------------------------- | :-------: | --------------------------------------------------------------------------------------- |
| Ver+HL                            |     1     | version : IP 버전 (4bits)<br>+<br>HL : 헤더 길이 (4bits)                                      |
| TOS                               |     1     | 트래픽 처리 특성 등을 표시                                                                         |
| Total Length<br>                  |     2     | 헤더와 데이터를 합친 IP 패킷 전체 길이                                                                 |
| Identification                    |     2     | 조각난 패킷을 재조립할 때 식별                                                                       |
| Flags+FO                          |     2     | flags : 조각화 금지·추가 조각 여부 등 (3bits)<br>+<br>Fragment Offset : 원래 데이터에서 해당 조각의 위치 (13bits) |
| TTL                               |     1     | 라우터를 통과할 때 감소하는 값                                                                       |
| Protocol Type                     |     1     | 내부 데이터가 TCP·UDP·ICMP 등인지 표시                                                             |
| Header Checksum                   |     2     | IPv4 헤더의 오류 검사                                                                          |
| Source IP Address                 |     4     | 출발지 IPv4 주소                                                                             |
| Destination IP Address            |     4     | 목적지 IPv4 주소                                                                             |
| **총합** (기본 헤더)                    |  **20**   | 최소 크기                                                                                   |
| +                                 |     +     |                                                                                         |
| Option + Padding                  |    40     |                                                                                         |
| **총합** (기본 헤더 + Option + Padding) |  **60**   | 최대 크기                                                                                   |

✓ **IP Packet의 최대 크기 -> 65535**

Header가 최소 크기(20Bytes) 일 때 Payload => 65535 - 20 = 65515 Bytes
Header가 최소 크기(20Bytes) 일 때 Payload => 65535 - 60 = 65475 Bytes

# 2. 프로토콜별 헤더구조

## 2.1 ARP Header (L2)

![[00. Setting/00. 첨부파일/Pasted image 20261116171913.png]]

| 이름                             | 크기 <br>(Bytes) | 설명                                                                                                    |
| ------------------------------ | :------------: | ----------------------------------------------------------------------------------------------------- |
| Hardware type                  |       2        | 네트워크 유형을 나타냄                                                                                          |
| Protocol type                  |       2        | IPv4, IPv6, ATM 등 프로토콜 정의                                                                             |
| Hardware Address size / Length |       1        | 이 필드에 저장되는 이더넷(=MAC 주소)의 경우 6 Bytes                                                                   |
| Protocol Address Length        |       1        | ARP request ------ 1 (code)<br>ARP reply --------- 2<br>RARP request ----- 3<br>RARP reply -------- 4 |
| Operation code                 |       2        | -                                                                                                     |
| Sender Hardware Address        |       6        | -                                                                                                     |
| Sender Protocol Address        |       4        | -                                                                                                     |
| Target Hardware Address        |       6        | -                                                                                                     |
| Target Protocol Address        |       4        | -                                                                                                     |
| **총합**                         |     **28**     | -                                                                                                     |
|                                |                |                                                                                                       |

✓ **일반적인 ARP 요청은 브로드캐스트로 보낸다**
    => 상대의 MAC 주소를 모르니 일단 모두에게 물어보는 것

이때 이더넷 목적지 MAC 주소 => FF:FF:FF:FF:FF:FF (같은 LAN에 전체 전달)
FF는 이진수로 `11111111`이 된다. MAC주소의 48비트를 모두 1로 채우면 같은 LAN/VLAN의 모든 장치에게 보내는 주소가 된다.

✓ **ping은 ICMP Echo 메시지를 이용해 응답 여부를 확인한다**

e.g) `ping -c 1 -p 414141 192.168.59.133` (414141=> ascii code:aaa)
    -> a 세 개 담은 패킷 전송

**그렇다면 ascii code로 명령 실행도 가능하지 않을까?**

whoami
    -> `ping -c 1 -p 77686.... 192.168.59.133`

이런 식으로 명령 실행도 할 수 있다(구형 os만 가능).

## 2.5 TCP Header (L4)

![[00. Setting/00. 첨부파일/Pasted image 20261117032424.png]]

| 이름                    | 크기<br>(Bytes) | 설명                                                                                                                                                                       |
| --------------------- | :-----------: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Source Port           |       2       | 출발지 포트 번호                                                                                                                                                                |
| Destination Port      |       2       | 목적지 포트 번호                                                                                                                                                                |
| Sequence Number       |       4       | 이 세그먼트에 담긴 데이터의 시작 순서 번호                                                                                                                                                 |
| Acknowledgment Number |       4       | 상대방에게 다음으로 받기를 기대하는 순서 번호                                                                                                                                                |
| DO+Resv+Flags         |       2       | Data Offset : TCP 헤더 길이 (4bits)<br>+<br>Reserved : 예약 영역 (3bits)<br>+<br>Flags : 연결 설정·종료, 수신 확인 등을 나타내는 제어 비트(CWR, ECE, URG, ACK, PSH, RST, SYN, FIN) (9bits - 각 1bits) |
| Window Size           |       2       | 수신 측이 받아들일 수 있다고 알리는 데이터 양                                                                                                                                               |
| Checksum              |       2       | TCP 헤더와 데이터 등의 오류 검출                                                                                                                                                     |
| Urgent Pointer        |       2       | 긴급 데이터의 끝 위치를 나타내는 값. URG가 1일 때 유효                                                                                                                                       |
| **총합**                |    **20**     | 기본 헤더 크기                                                                                                                                                                 |
| +                     |       +       | -                                                                                                                                                                        |
| Options + Padding     |     0~40      | 추가 기능                                                                                                                                                                    |
| **총합**                |   **20~60**   | -                                                                                                                                                                        |

✓ **헤더 길이 계산법**

Data Offset이 5이면 5 × 4 = 20Bytes
Data Offset이 15이면 15 × 4 = 60Bytes

즉, Data Offset은 헤더가 어디까지고 실제 데이터는 어디서 시작하는지 알려준다.

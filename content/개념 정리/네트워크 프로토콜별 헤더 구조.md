# 1. 데이터 캡슐화의 과정

**데이터는 Header들의 연속된 집합**

<br><br>

### 1.1 L1 : Physical Header

     => 수신 준비와 프레임 시작 표시

| 이름       | 크기 <br>(Bytes) | 설명                     |
| -------- | :------------: | ---------------------- |
| Preamble |       7        | 송신 측과 수신 측의 비트 타이밍을 맞춤 |
| SFD      |       1        | 프레임의 시작을 표시            |
| 총        |       8        | -                      |

<br><br>

### 1.2 L2 : Ethernet Frame Header

| 이름                      | 크기 <br>(Bytes) | 설명                   |
| ----------------------- | :------------: | -------------------- |
| Destination MAC Address |       6        | 받는 장치의 MAC 주소        |
| Source MAC Address      |       6        | 보내는 장치의 MAC 주소       |
| Type or Length          |       2        | 내부 프로토콜 종류 또는 데이터 길이 |
| 총 (Header)<br>          |       14       | -                    |
| +                       |       +        | -                    |
| Data + Padding          |    46~1500     | 전달할 내용과 필요시 채우는 공간   |
| FCS                     |       4        | 전송 중 오류 검사용 값        |
| 총 (Header+Trailer)      |    64~1518     | -                    |

- Trailer: 프레임 뒤에 붙는 부분을 가리키는 말

<br><br>

### 1.3 L3 : IP Header

| 이름                           | 크기(Bytes) | 설명                                                                                      |
| ---------------------------- | :-------: | --------------------------------------------------------------------------------------- |
| Ver+HL                       |     1     | version : IP 버전 (4bits)<br>+<br>HL : 헤더 길이 (4bits)                                      |
| TOS                          |     1     | 트래픽 처리 특성 등을 표시                                                                         |
| total length<br>             |     2     | 헤더와 데이터를 합친 IP 패킷 전체 길이                                                                 |
| identification               |     2     | 조각난 패킷을 재조립할 때 식별                                                                       |
| Flags+FO                     |     2     | flags : 조각화 금지·추가 조각 여부 등 (3bits)<br>+<br>Fragment Offset : 원래 데이터에서 해당 조각의 위치 (13bits) |
| TTL                          |     1     | 라우터를 통과할 때 감소하는 값                                                                       |
| protocol type                |     1     | 내부 데이터가 TCP·UDP·ICMP 등인지 표시                                                             |
| header checksum              |     2     | IPv4 헤더의 오류 검사                                                                          |
| Source IP Address            |     4     | 출발지 IPv4 주소                                                                             |
| Destination IP Address       |     4     | 목적지 IPv4 주소                                                                             |
| 총 (기본 헤더)                    |    20     | 최소 크기                                                                                   |
| +                            |     +     |                                                                                         |
| Option + Padding             |    40     |                                                                                         |
| 총 (기본 헤더 + Option + Padding) |    60     | 최대 크기                                                                                   |

IP 패킷의 최대 크기 -> 65535

헤더가 최소 크기(20Bytes) 일 때 페이로드 => 65535 - 20 =

payload : data 65475 - 65515

# 1. ARP Header

![[00. Setting/00. 첨부파일/Pasted image 20261116171913.png]]

| 이름                             | 크기 <br>(Bytes) | 설명                                                                                                    |
| ------------------------------ | :------------: | ----------------------------------------------------------------------------------------------------- |
| Hardware type                  |       2        | 네트워크 유형을 나타냄                                                                                          |
| Protocol type                  |       2        | IPv4, IPv6, ATM 등 프로토콜 정의                                                                             |
| Hardware Address size / Length |       1        | 이 필드에 저장되는 이더넷(=MAC 주소)의 경우 6 Bytes                                                                   |
| Protocol Address Length        |       1        | ARP request ------ 1 (code)<br>ARP reply --------- 2<br>RARP request ----- 3<br>RARP reply -------- 4 |
| Operation code                 |       2        | -                                                                                                     |
| Sender Hardware Address        |       6        | -                                                                                                     |
| Sender Protocol Address        |       4        | -                                                                                                     |
| Target Hardware Address        |       6        | -                                                                                                     |
| Target Protocol Address        |       4        | -                                                                                                     |
| 총                              |       28       | -                                                                                                     |

✓ **일반적인 ARP 요청은 브로드캐스트로 보낸다**
    => 상대의 MAC 주소를 모르니 일단 모두에게 물어보는 것

이때 이더넷 목적지 MAC 주소 => FF:FF:FF:FF:FF:FF (같은 LAN에 전체 전달)
FF는 이진수로 `11111111`이 된다. MAC주소의 48비트를 모두 1로 채우면 같은 LAN/VLAN의 모든 장치에게 보내는 주소가 된다.
